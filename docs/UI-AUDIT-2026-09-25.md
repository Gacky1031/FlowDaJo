## 先に固定する設計規則

1. Global worksheetは1枚に1サンプル。サンプル切替で軸・配置を変えない。Normal worksheetは各項目にサンプルを固定し、混在比較する。
2. **表示細胞集団**、**ゲート輪郭の表示**、**点の集団色**は独立した設定である。軸が違っても表示集団は変更できる。
3. 要求された分画が存在しなければ「存在しない」と示す。親集団・All eventsへの暗黙の置換をしない。
4. プロット・統計・コンペは同じワークシート項目として選択、移動、整列、複製、Normalでの展開を扱う。
5. 未適用の編集値、適用済みの解析設定、表示だけの設定を分けて保持する。描画更新で編集中の値を消さない。
6. 印刷はワークシートの表示設定とA4枠を反映する。プレビューで確認した内容をそのまま保存する。
7. 分画名は表示名であり、同一性の唯一の根拠にしない。改名で非表示設定や参照が壊れないようにする。

### F01 — reportが別の細胞集団を出力する

根拠: [r/worksheet.R:668](../r/worksheet.R#L668)。`report_population()` は分画が見つからないとpathの末尾を繰り返し削り、解決できる親まで戻る。すべて欠けている場合はrootに戻る。固定サンプルのカードにもこの処理が入る。

実際のdispatchにA/Bサンプル、Global P1、Aだけの個別P2、要求path `P1/P2` を渡した結果:

```text
A: P1/P2
B: P1       ← P2が存在しないことを報告せず、解析対象を変更
```

**修正:** 元の要求pathを保持し、対象サンプルの当該カードを「分画なし」とする。出力前に欠損一覧と扱いを提示する。スキップを選べるとしても、親集団への置換を通常動作にしない。

**合格条件:** AにしかないP2を全サンプルreportに含めても、BのP1やAll eventsのイベント数がP2の代わりに出力されない。プレビュー、PDF、出力結果の欠損一覧が一致する。

### F02 — Normalの軸範囲同期が収束しない

根拠: [src/main.ts:450](../src/main.ts#L450)、[src/main.ts:490](../src/main.ts#L490)、[src/main.ts:566](../src/main.ts#L566)。

同じ軸・集団の2カードで、一方が手動 `[0,100000]`、他方が自動・既存範囲 `[0,200000]` のとき:

1. 同期目標は手動範囲 `[0,100000]` になる。
2. 自動側の実範囲との差から `needsAnalyze=true` になる。
3. `setRange()` は自動範囲の縮小を拒むため、`[0,200000]` のまま。
4. 結果受信時に再解析し、同じ条件に戻る。

ソース関数を3回呼び、3回とも範囲不変・`needsAnalyze=true` を確認した。ジョブの「古い結果を捨てる」機構ではこの循環は止まらない。

**修正:** Globalの初回固定とNormalの比較範囲決定を分離する。次の設定をまず計算し、実際に設定が変わったときだけ再解析する。異なる手動範囲が複数ある場合の規則も定義する。先頭カードの設定を無条件に正解としない。

**合格条件:** 上記のケースが有限回でReadyになる。2回目以降に同じ入力を渡すと変更なしになる。Globalのサンプル切替では軸を維持し、Normalの異なる集団や独立した手動範囲を意図せず巻き込まない。

### F03 — コンペの編集中の値が再描画で失われる

根拠: [src/main.ts:647](../src/main.ts#L647)、[src/main.ts:2257](../src/main.ts#L2257)、[src/main.ts:3037](../src/main.ts#L3037)。入力は適用ボタンを押すまでDOMだけにあり、再描画は保存済みの行列から入力欄を作り直す。

1. FITC-A→PE-Aを `13` から `21.5` に編集する。
2. 「補正 ON」をチェックする。
3. 表示蛍光APC-Aのチェックを切り替える。

**修正:** サンプルに紐づく `CompensationDraft` を状態として保持する。「未適用」「プレビュー中」「適用済み」を表示する。表示蛍光・配置・選択などの変更はdraftを変えない。サンプル変更時はdraftを保持して戻せるか、明示的に破棄・適用を選べるようにする。

**UI改善:** プロットを見ながら調整できるよう、選択中サンプルへの短いデバウンス付きプレビューと、チェックした他サンプルへの確定適用を分ける。ON/OFFのチェックがまだ適用されていない場合はそれを明示する。行列の変更セルを強調し、適用先の件数・サンプル名を表示する。

**合格条件:** 21.5というdraftが表示蛍光の切替、ウィジェット移動、無関係な項目の追加で消えない。適用はチェック先だけ、Undoは1操作単位で戻る。行列が不正な場合、対象サンプルを部分的に更新しない。

### F05 / F06 — サンプル並び替えは2箇所を直す必要がある

**F05:** [src-tauri/tauri.conf.json:14](../src-tauri/tauri.conf.json#L14) には `dragDropEnabled` の指定がない。Tauri CLIの設定スキーマは既定値をtrueとし、WindowsでHTML5 DnDを利用するには無効化が必要と説明している。一方、サンプル・分画のドラッグはHTML5の `dragstart/drop` に依存する。Rust側での無効化も見当たらない。

これはWindowsでの手動並び替え不調の原因候補として優先して確認すべき設定不整合である。**ブラウザのDnDテスト成功だけでは修正完了にしない。** ネイティブファイルドロップとの必要性を整理し、WebView設定かアプリ内ドラッグ方式を統一する。

**F06:** [src/main.ts:897](../src/main.ts#L897) の上下ボタンは上移動で `insertAfter=true`、下移動でfalseを渡している。[reorderSample:764](../src/main.ts#L764) の仕様と逆で、隣の前後に戻り、順序が変わらない。デモ2サンプルで2番目の↑を押しても順序不変だった。

**合格条件:** A/B/CからBを上へ→B/A/C、Aを下へ→B/A/C。ドラッグ・ボタン・保存再読込で同じ順序になる。名前順・取り込み順からドラッグしたら手動順に移る。Windows実機でサンプル並び替えと分画ドロップを両方確認する。↑↓キーによる選択移動と順序変更を混同しない。

### F07 — Shift選択とドラッグ開始の処理が競合する

**合格条件:** Shift/Ctrl/Cmd、見出し／プロット余白、矩形選択、右クリック、混在ウィジェットで対象集合が一致する。入力欄・軸クリックでは選択を壊さず、修飾キー操作後もプロットが描画される。

### F15 — Normalで3サンプル以上比較するとキャッシュの効果が落ちる

根拠: [r/worksheet.R:11](../r/worksheet.R#L11)、[r/worksheet.R:76](../r/worksheet.R#L76)。サンプル保持数は2固定だが、ワークシート処理は必要サンプルを順に全件評価する。A/B/Cの順で繰り返すと、前回のB/Cを次回のA/B読み込みが追い出し、3サンプルとも毎回読み直す条件になる。

速度低下の大きさは未計測。Normalの複数サンプル比較という用途に対して不利な設計であり、まず計測すべき。

**修正・合格条件:** raw読込、補正、gate masks、plotデータの所要時間とキャッシュhitを計測する。件数固定を単純に巨大化せず、メモリ予算、依存したサンプル／ゲートだけの無効化、必要なら表示範囲単位の要求にする。3/10サンプルで1ゲート変更時のFCS再読込数とメモリを比較し、メモリ予算内の未変更サンプルを反復読込しない。

### F16 — 四分割ゲートが新しい色を消費する

根拠: [src/main.ts:1485](../src/main.ts#L1485)。すべての新規ゲートにpaletteから色を設定し、四分割の4個にもその新しい色を配る。最深階層を優先する描画では、親分画を四分割しただけで親のほぼ全イベントが新しい同一色に置き換わる。

ユーザーの「四分割は新しい色を作らなくてよい」という規則と合わない。

**修正・合格条件:** 四分割は親の有効色を継承することを既定とする。より深い通常ゲートの色は引き続き優先する。四分割グループの編集・削除・スコープ変更が一括で行われる既存仕様を維持する。
